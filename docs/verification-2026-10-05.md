# 登録・OAuthの通し検証結果

対象ジョブ: `live-test-001`。状態: **ready**。

| 検証箇所 | 結果 |
| --- | --- |
| Cloudflare Catch-all | 検証環境の受信ドメインからEmail WorkerへのルーティングをAPIで確認 |
| 新規メール登録 | ConsoleのregisterがHTTP 200 |
| 実メール受信 | Worker経由で確認URLを取得 |
| ブラウザーの継続 | 登録と同じCloakBrowserでメールを確認、sessionがHTTP 200 |
| アカウント照合 | 登録アドレスとブラウザーのログインアドレスが一致 |
| OAuth | `opencode console login` がデバイス認可後にログイン成功を出力 |
| 保存・再起動 | `console orgs` が同じアカウントのPersonalワークスペースを認識 |
| Go SDK | Acksell SDK v1.18.34でhealth、モデル一覧、SSE接続、生成に成功 |
| 無料モデル | `opencode/big-pickle` が `OK` を返した |
| ジョブ再開 | OAuth保存済み状態から、ブラウザーを開かずSDK疎通確認を再実行してreadyへ更新 |

主な修正:

- ブラウザーをEdgeからCloakBrowserへ変更した。固定1100×850 viewportをやめ、実ウィンドウ追従と67%表示を導入した。
- 登録途中でウィンドウを閉じても、スクリーンショットの失敗が進捗保存を妨げないようにした。
- WranglerのOAuth更新を先に行い、期限切れアクセストークンによるルーティング確認の403を解消した。
- GoのSDKバージョン指定を、実際に導入できる `@v1.18.34` に修正した。
- モデルエラーを公式CLIでも再現し、ツール一括拒否設定が原因と特定した。確認必須設定に変更すると成功した。
- 完了後に残っていたPromise.raceのタイマーでプロセス終了が遅れる問題を修正した。

この結果は1アカウントの実登録・OAuth・短い生成の検証であり、数百件の登録成功率や長時間のトークン更新を保証するものではない。数百アカウントのスケジューラーとOpenAI互換APIサーバー本体は今後の実装対象。

メール、パスワード、OAuth状態は `.state/onboarding/live-test-001/` に保存。公開用ドキュメントには秘密情報を記載していない。
